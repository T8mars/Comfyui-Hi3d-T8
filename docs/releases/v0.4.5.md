# Hi3D T8 v0.4.5

独立工作台修复复杂网格 UV 重复展开与进度缺失问题。默认按 CuMesh 原生→社区 GPU PEC→有界 CPU 分区选择，增加源对应校验、局部 UV 修复及内容绑定缓存，普通路径减少额外依赖冷读；已有模型贴图不减面。新建 TRELLIS.2 几何可选 10／30／100 万面预算，默认 100 万，原始几何另存。

网页与启动窗口显示真实阶段、环节进度、耗时和明确的 CPU／CUDA 执行位置。采样支持两种步数字段，回车进度条中混入的 JSON 事件可以正常识别；无分母计数不伪造百分比或 ETA。日志继续保留。

模型页支持自定义权重根目录，显示实际与配置路径；绝对／相对目录均可空闲保存并立即生效，无需重启，恢复默认不搬移或删除模型。目录配置随代码更新保留。TRELLIS 网格体素化按真实 CPU 路径显示，仅在编码器 forward 开始后标为 CUDA。

TRELLIS.2 新增自动／原生 FlashAttention／融合 SDPA 选择；Hi3D 设置独立。可选原生注意力与 Numba 轮子按 ABI、大小和 SHA256 检查后安装，不自动升级 Torch／NumPy。原生 packed CUDA 探针通过；局部内核样例更快不代表整任务提速，完整几何对照 SDPA 359.211 秒、原生 505.729 秒，受加载／PageIn 等开销影响。详见[性能说明](../PERFORMANCE.zh-CN.md)。

原问题网格的 973,926 个有效面已通过 UV 与缓存回读：CuMesh 65.155／1.275 秒，社区路径 162.418／1.437 秒，仅移除 42 个精确退化面。社区测量含依赖冷读和首次 JIT，不宣称普遍 2.5 倍算法提速。四份实际 GLB 重载的位置、法线、完整有向面及 UV 检查通过。CPU 全套回归 567 项通过（57.91 秒，1 条依赖弃用警告）。完整包已完成两组可选轮子安装与 `pip check`，模型推理另行真实验收；浏览器入口不可用，新版交互未验收，见[验证记录](../../VALIDATION.md)。历史失败的 UV 尝试不计为成功。

E 盘真实 EXE 已完成百万面级 TRELLIS.2 PBR（1024／12 步／4K）：报告 766.36 秒，其中 UV 69.358 秒、采样 45.61 秒；原生稀疏 packed 调用 720 次。实际输出保留 973,926 有效面、两张嵌入 4K 材质，源几何／法线／UV 对照、三视角渲染与 80 mm 保材质导出通过。

第二次真实 PBR 从中文带空格的自定义根完成，实际观察 CPU 体素化→CUDA 编码→采样→CUDA 光栅化→CPU 四张贴图补边，忙时切目录 409、完成后恢复默认均通过。1,280 面／512／4 步／1K 小案例总耗时 192.625 秒，用于功能回归，不与大网格作速度比较。测试目录为原权重的 junction 别名，没有搬移／复制全量模型。

ComfyUI 节点和画布工作流保持 Hi3D-only。GitHub 附件仅含代码与小型启动器，不含 Python 或模型；完整整合包另行提供，代码更新保留模型、运行时、设置和任务记录。

---

The standalone workbench adds verified UV caching and local repair, with the default order native CuMesh → community GPU PEC → bounded CPU partitions. Both GPU-assisted UV routes and cache reloads passed on the original complex mesh, retaining all 973,926 valid faces. CuMesh took 65.155 seconds initially and 1.275 seconds from verified cache; the community route took 162.418/1.437 seconds with cold-loading/JIT overhead. These are not whole-task speedup claims. Existing-model texturing preserves geometry; newly generated TRELLIS geometry offers 100K/300K/1M face budgets with the raw mesh retained.

The browser and launcher show actual stage/phase progress and explicitly reported devices. Inline JSON events mixed with stderr progress displays are recovered; unknown totals do not produce invented percentages or ETAs. TRELLIS.2 gains independent auto/native FlashAttention/SDPA selection and optional pinned acceleration wheels. Kernel benchmarks do not establish whole-task acceleration: the measured complete geometry runs took 359.211 seconds with SDPA and 505.729 seconds with native attention. See [performance and limits](../PERFORMANCE.md).

The model page supports an absolute or workbench-relative model root, applied immediately while idle with no restart or automatic file movement. Code updates preserve the setting. TRELLIS voxelization is reported as CPU preparation, with CUDA encoding reported only at the actual encoder forward call.

All four UV GLBs passed position/normal/oriented-face/UV checks after actual re-import. The E-drive EXE also completed the complex 1024/12-step/4K PBR run, retaining all 973,926 valid faces; actual GLB/material comparison, three-view rendering and an 80 mm material-preserving export passed. The pipeline report was 766.36 seconds, including 69.358 seconds of UV and a 45.61-second sampling loop. A second 1,280-face/512/four-step/1K task passed from a Chinese/space-containing custom model root, including corrected CPU/GPU events, busy-switch rejection and restoring the default. Its 192.625 seconds are a functional regression result, not a speed comparison with the large case; junction aliases reused the existing weights.

The final frozen-code CPU suite passed 567 tests in 57.91 seconds, including model-path UI/backend and encoding/baking progress regressions. Optional-wheel installation and `pip check` passed in the complete bundle. Fresh browser interaction is unverified because the browser surface is unavailable. ComfyUI remains Hi3D-only. GitHub assets contain code and a small launcher, with no Python or model weights; the complete bundle is distributed separately.
