日期：2026-10-24。主体案例为真实图片建模粗模经过 Hi3D 512 / 25 步后，再执行真实 TRELLIS.2 PBR 贴图的兔子角色。本复核直接查看参考图与实际 GLB 渲染的六个视角；兔子部分未重渲染。机械高档及 portable 建筑补充使用实际 GLB 做了 CPU 六视图渲染，见末两节。视觉复核没有启动 GPU 或以浏览器夹具替代真实结果，也没有以模型成功报告代替看图。

## 结论

**PBR 已形成可辨识的完整角色，主要色块和图案有对应关系，但尚不能称为参考的精确复现。** 眼睛、耳内、腮红、粉色鼻子、胸牌、手套和蓝白鞋都能识别；主要问题是嘴部黑纹粗碎、服装由参考的桃橙色偏向粉色、鞋呈现更饱和的深蓝。已有的嘴和眼部几何突起没有被贴图修复，部分反而因黑白纹理对比更醒目。

随后已完成同图、同种子的“粗模直接贴图”六视图对照。**在本兔子案例中，图片建模先走粗模 → PBR 更合适，Hi3D 保持可选。** 直贴版本的笑嘴、暖色衣服和耳内颜色更接近参考；Hi3D 版本背头更平滑，但不足以抵消脸部局部恶化。工作台图片建模入口已采用默认关闭精修、开启 PBR 的保守起点，用户仍可主动勾选 Hi3D；对照详情如下。

## 默认设置建议与限制

1. 基于本次真实成对结果，建议图片建模默认先 **粗模 → PBR**，Hi3D 作为用户可选步骤；保留粗模、精修几何和材质结果的独立预览/导出。需要更平滑大曲面时再尝试 Hi3D，并检查脸、鞋等关键部位。这是保守默认建议，不是所有资产类别的普遍结论。
2. 前端图片建模初始状态和入口切换默认关闭 Hi3D、保持 PBR 开启；模型精修入口仍必须运行 Hi3D。隔离 Chrome 已验证默认两阶段 payload/摘要、主动勾选后三阶段 payload/摘要，以及 `mode=refine` 强制精修。既有 10 组检查加必要边界共 12 组通过，JavaScript 错误 0；这些前端检查使用明确的 HTTP 夹具，不能替代本报告依据真实渲染得出的效果结论。
3. 当前 2048 贴图已经能承载主要角色图案；没有 4096 对照，不能保证提高贴图尺寸会修复嘴型、色调或几何硬沟槽。
4. 展示结果时可明确说明“真实图片生成粗模、可选真实 Hi3D、真实 PBR 与保材质导出均已产出”；应保留直贴的层带/鞋头图案问题、精修版的嘴部问题，以及单视图背面的不确定性。

本轮同时明确了界面参数适用范围：Hi3D 步数与 Attention 只在运行 Hi3D 几何精修时显示；纯贴图或关闭精修的图片流程仍保留随机种子和省显存模式。该界面修正不改变贴图阶段的实际采样设置。
